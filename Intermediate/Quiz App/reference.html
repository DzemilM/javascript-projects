Quiz App — scaffold reference

Everything the HTML and CSS hand you, on one page. The markup, styling and questions are written; js/script.js is yours.

The shape of it

All three screens sit in the page at once. Two carry is-hidden. Nothing is created or destroyed when you switch — you just move that class.

state→ render fn→ DOM| event→ change state→ render again

State is the truth, the screen is only a picture of it. Same idea as useState, except you call the render yourself.

Buttons already wired

startButton, restartButton and nextButton have their listeners at the bottom of script.js. You never touch them again — you just write the functions they call.

Only two are containers

answerList and resultsList are the only elements you build into. Every other one, you set textContent or toggle a class. That is the whole surface.

State

let state = {
  currentIndex: 0,      // which question, 0-based
  score: 0,             // +1 correct, -1 timed out
  answered: false,      // stops a second click scoring twice
  timeLeft: 60,         // seconds on the current question
  intervalId: null,     // so the clock can be stopped
  results: [],          // { questionId, selected, timedOut }
};

Doing maths? You want state.currentIndex. Reading text? You want QUESTIONS[state.currentIndex].

Helpers already written

showScreen(el)shows one screen, hides the other two
formatTime(s)47 → "0:47"
stopTimer()kills the interval, safe to call any time

Plus QUESTIONS and SECONDS_PER_QUESTION from js/data.js, and LETTERS for the A/B/C/D.

Order to write them

  1. renderQuestion — question on screen
  2. startQuiz — reset state, show the question screen ← playable after this
  3. handleAnswer — score it, show feedback
  4. goToNext — advance, or show results
  5. renderAnswered — paint the buttons red/green
  6. startTimer — the countdown
  7. updateTimerDisplay — draw the clock and bar
  8. renderResults — the final screen
  9. handleTimeout — the −1 penalty

Numbered by the order to tackle them, not the order they appear in the file.

Testing a function before the app can reach it

Everything is a global in a classic script, so the console can call it: 

showScreen(questionScreen); renderQuestion();
  • Buttons unstyled → a class name is misspelled
  • Letters missing → spans appended to the wrong parent
  • Same answer four times → a hardcoded value where answer or i belongs
